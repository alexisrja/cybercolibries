Abrir un archivo PCAP con miles de paquetes puede ser abrumador. La clave es **no leer paquete por paquete**, sino hacerle preguntas a la captura. Los filtros de visualización son esas preguntas.

<Callout type="nota">
  Los *filtros de captura* (sintaxis BPF) deciden qué se guarda. Los *filtros de visualización* deciden qué ves. En esta guía hablamos de los segundos.
</Callout>

## 1. Empieza por el panorama

Antes de filtrar, abre **Statistics → Conversations** y **Statistics → Protocol Hierarchy**. En dos minutos sabrás qué hosts hablan más y qué protocolos predominan.

## 2. Filtros por host y puerto

```text
ip.addr == 10.0.0.23
ip.src == 10.0.0.23 && ip.dst != 10.0.0.0/8
tcp.port == 443
udp.port == 53
```

El segundo filtro es muy útil: muestra lo que un host interno envía **hacia fuera** de la red.

## 3. DNS: la bitácora de intenciones

Casi todo empieza con una consulta DNS. Revisarlas te dice a dónde *quería* ir cada equipo.

```text
dns.flags.response == 0
dns.qry.name contains "update"
dns.qry.name.len > 50
```

Nombres de dominio muy largos o con apariencia aleatoria pueden indicar **DGA** o túneles DNS.

## 4. HTTP y TLS

```text
http.request.method == "POST"
http.request && !(http.host contains "empresa.com")
tls.handshake.type == 1
tls.handshake.extensions_server_name contains "paste"
```

Aunque el tráfico TLS esté cifrado, el campo **SNI** del Client Hello suele revelar el dominio de destino.

## 5. Señales de problemas

```text
tcp.flags.syn == 1 && tcp.flags.ack == 0
tcp.analysis.retransmission
icmp.type == 8
```

Muchos SYN sin respuesta hacia puertos distintos suelen ser un escaneo.

## Un método para no perderte

1. Anota la **hora de inicio** y los **hosts involucrados**.
2. Filtra por el host sospechoso y revisa su DNS.
3. Sigue las conexiones más grandes con *Follow → TCP Stream*.
4. Registra cada hallazgo con número de paquete y hora.

Con este método puedes resolver el challenge **Network Investigation**. Lo importante no es encontrar todo, sino poder explicar lo que encontraste.
